## Database and API design

Use InnoDB, explicit foreign keys, exact integer minor units, date-only fields for business days, and UTC for event timestamps. Keep Nepal business dates in `Asia/Kathmandu` and retain the existing frontend BS converter and supported boundaries. Replace JSONB with validated JSON and map arrays to JSON when they are transferred as a unit. Retain UUIDs as ASCII identifiers. Model identity sequences with auto-increment or locked numbering rows according to how each identifier is consumed. Preserve nullable and case-insensitive unique-key semantics explicitly. Map each RLS policy and grant to an endpoint and projection before exposing data. Browser callers never choose a SQL table, arbitrary column or routine.

Use domain endpoints under `/api`. Return the existing UI's row shapes via typed frontend adapters. Validate money, counts, status transitions and dates on the server. Log important changes in the same transaction as the corresponding mutation. The online user accesses only the target database through PDO. Migration credentials are scoped separately.

Rehearse migration from a verified snapshot and media manifest. Load into a fresh target in dependency order with foreign-key checks on. Validate counts, identifier parity, payment totals by period, invoices by status, balances and inventory movements. Compare the source and destination reports before approving cutover. Keep the previous app available until the rehearsal and user acceptance checks pass.
